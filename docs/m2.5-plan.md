## 4. Plan paso a paso

### Fase A · Preparación local (sin servicios externos) ✅ completada
- **A1. Conflictos sin depender solo del reloj local**:
  - Cada operación lleva la *versión que el dispositivo vio* (`base_seq` de la fila). Si nadie ha cambiado la fila desde entonces, se aplica sin mirar relojes.
  - Si hubo un cambio concurrente, se usa un reloj **corregido con la hora del servidor**: el cliente estima su desfase en cada respuesta y aplica un *hybrid logical clock*, que nunca va por detrás de lo ya visto.
  - Así, un móvil con la hora mal no puede «ganar» a un cambio posterior.
  - Nueva migración y tests de integración y E2E con relojes desfasados.
- **A2. Cerrar sesión borrando la copia local**: casilla «Borrar los datos de este dispositivo (tu cuenta en la nube no cambia)». Si hay cambios pendientes, primero se intenta sincronizar y se avisa de lo que se perdería. Borra IndexedDB del usuario y la caché; nunca toca la nube.
- **A3. Endurecimiento para producción**:
  - Cookies `Secure`.
  - Cabeceras de seguridad (CSP, HSTS, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`).
  - Validación de variables al arrancar.
  - `vercel.json` con región `fra1`.
- **A4. Guarda de proyecto cloud**:
  - `supabase/cloud-project.json` contiene ref, nombre y organización esperados (no son secretos).
  - `npm run cloud:check` compara el destino real con ese fichero; `cloud:push` solo ejecuta `db push` tras el *dry run* y esa verificación.
  - Bloqueo explícito del proyecto y la organización de Uría (guardados solo como huellas SHA-256).
- **A5. Copias y restauración**:
  - `npm run backup:cloud` crea un dump lógico cifrado del proyecto cloud, con la cadena de conexión pasada solo en tiempo de ejecución.
  - `npm run restore:drill` lo restaura en el **stack local** y compara recuentos y sumas de control por tabla.
  - El simulacro se ensaya primero de local a local.
- **A6. Diagnóstico de sincronización** en Ajustes: dispositivo, cambios pendientes, último pull, desfase de reloj estimado y botón de forzar resincronización completa. Sirve para la validación con dispositivos reales.
- **A7. Pruebas *smoke* contra la URL HTTPS** (`BASE_URL=...`): login, redirecciones, cabeceras, manifest y `/auth/confirm` con token inválido. Más una guía manual de pruebas móvil-PC.

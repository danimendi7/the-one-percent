# M2.5 · Validación en dispositivos reales

Se ejecuta tras el despliegue HTTPS (Fase C). Dispositivos: **móvil** (iPhone con Safari o Android con Chrome) y **ordenador** (Chrome o Edge). Anota resultado y hora en cada paso. En el móvil, Ajustes → «Diagnóstico de sincronización» muestra los cambios pendientes, el último pull y el desfase de reloj.

## C4 · Comprobaciones automáticas del despliegue
```bash
BASE_URL=https://<app>.vercel.app npm run smoke
```
Esperado: 12/12. Cubre redirección a login, HTTPS y HSTS, CSP y cabeceras, accesibilidad del login, enlace inválido, manifest e iconos, y demo sin llamadas al servidor.

## C6 · Sincronización real móvil ↔ ordenador
| # | Paso | Esperado |
| --- | --- | --- |
| 1 | Ordenador: crea «Leer 20 min» (Duración, cada día) | Aparece en el móvil en 1–2 s sin recargar |
| 2 | Móvil: registra 25 min con un valor rápido | Aparece en el ordenador; indicador «Sincronizado» |
| 3 | Móvil en **modo avión**: marca 2 hábitos | Indicador «Sin conexión · 2 en cola»; la UI responde al instante |
| 4 | Cierra la app del móvil (también desde multitarea), reábrela aún sin red | Los 2 cambios siguen ahí, pendientes |
| 5 | Quita el modo avión | «Sincronizado»; en el ordenador aparecen exactamente 2 registros |
| 6 | Pon la hora del móvil **manualmente 3 h atrás**; marca en el ordenador y desmarca en el móvil tras verlo | Gana el móvil (edición secuencial); Diagnóstico muestra el desfase corregido |
| 7 | Con los dos online, edita el nombre del mismo hábito a la vez en ambos | Uno recibe «Se editó en otro dispositivo» con «Aplicar el mío» |
| 8 | Cambia la frecuencia de un hábito con historial | Las semanas pasadas conservan su porcentaje en Analítica |
| 9 | Marca hoy como descanso en el ordenador | El móvil muestra «Hoy es día de descanso» |
| 10 | Archiva un hábito en el móvil y restáuralo en el ordenador | Ambos convergen |
| 11 | Cierra sesión en el ordenador **activando «Borrar los datos de este dispositivo»** | Vuelve al login; al entrar de nuevo los datos llegan de la nube intactos |
| 12 | Exporta tus datos (Ajustes) en ambos | JSON con los mismos hábitos y registros |

## C7 · Copia y restauración
```bash
# Terminal del PC (variables solo para esta sesión; no se guardan)
$env:SUPABASE_DB_URL = "<cadena del Session pooler del proyecto cloud>"
$env:BACKUP_PASSPHRASE = "<frase larga guardada en tu gestor de contraseñas>"
npm run backup -- --source cloud              # → ~/Documents/the-one-percent-backups/top-cloud-….topbak
npm run restore:drill -- "<fichero>"          # restaura en el stack LOCAL y verifica tabla a tabla
```
Esperado: «✔ Restauración verificada: N tablas idénticas a la copia». El simulacro hace antes una copia automática del estado local y nunca escribe en el cloud.

Programación recomendada (Free): copia semanal manual o tarea programada de Windows, y copia antes de cada cambio de esquema. Opcional: GitHub Actions con secretos cifrados (requiere autorización aparte).
